# タスク
「AIのメッセージ終了時にユーザーの次の行動を促すボタン」の実装のタスクを整理するためのチェックリストです。
チェックリストを作成したりタスクが増えたら、ユーザーの指示がなくても編集してください。
チェックリストのタスクが完了したらユーザーの指示がなくても編集してください。

## やりたいこと
今はAIとチャットができて、AIが特定の形式で出力したらそれに対応したボタンが表示されてユーザーがアクションできるというツールになっている。
これを「AIコーディングエージェント」として実装を変更したい。

- 今、「AIのコード編集提案」のフロント側は次の2ファイルで実装してる
    - lua/senpai/presentation/chat/diff_block.lua : applyボタンの表示
    - lua/senpai/usecase/apply_replace_file.lua : applyボタンが押されて走る処理
- 今の流れ
    - ユーザーがメッセージを送信
    - AIの返信をサーバーサイドでパースして返す
        - AIが1つの返信に使えるツールは複数
    - コード編集の提案があれば、そのコード表示の近くにapplyボタンが表示される
    - AIのストリーミングが終了後、ユーザーが任意でapplyボタンを押す
- 上記の流れを、次のように変えたい
    - ユーザーがメッセージを送信
    - AIの返信をサーバーサイドでパースして返す
        - AIが1つの返信に使えるツールを1つに限定
    - (パース失敗の場合)diff_blockのdiffsにerrorsがあったらまとめてAIに送信
    - (以後パース成功の場合)アクションの提案があれば
        - チャットの履歴画面の下部に「Accept」「Reject」などのボタンが表示される
        - 例:「Accpet」を押したときらそのdiff_blockのdiffsの内容に従ってファイルを書き換え後、その旨をAIに送信
        - 例:「Reject」を押したらその旨をAIに送信
        - どちらのボタンを押しても、チャットの入力欄にユーザーが入力していればそれも添える
        - 「アクション」はAIが最後に返信したメッセージの中にあるツールに応じて変更する

- 現在フロント側がAIに送るメッセージ: ユーザーのメッセージ + リンク形式で書いたファイル( lua/senpai/usecase/send_text.lua )
- これからの実装でAIに送るメッセージ
    - 「ユーザーが書いたメッセージ」「diffsのerrosとして送るやつ」「Accept・Rejectを押したときの旨を送るやつ」などをAIが区別できるように表現したい
    - `<user>`とか`<errors>`みたいなタグの表現がまだ決まってないので、それを決めるタスクもいれる


### ツールの結果をAPIとして送るとき
そもそもユーザーのメッセージがないやつはこんな感じで`^\[.*\] Result:`の行があれば、それの行から下は全部結果の内容を書くだけにしたい(あえてタグを使わずに、パースを楽にしたい)

```markdown
[replace_in_file] Result:

成功しました、みたいな文章。
```

```markdown
[replace_in_file] Result:

エラーだったらエラーの内容
```
